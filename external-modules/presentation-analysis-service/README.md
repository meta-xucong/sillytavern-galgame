# Presentation analysis service

Optional loopback-only annotation service for the Galgame player. It labels visible assistant text for presentation; it does not generate story content or write to SillyTavern chats. The player browser does not connect to this service directly; it uses fixed browser-safe proxy routes on `visual-asset-service` at `127.0.0.1:8798`.

## Run

For the local game, run `external-modules/presentation-analysis-service/StartGalgamePresentationAnalysisService.cmd`. The service requires a Node runtime that provides `Intl.Segmenter` for grapheme-safe source-unit and refinement boundaries; the current local runtime (Node v24.14.1) provides it. The launcher reads only the three dedicated semantic-analysis values from ignored local `.env.local` (`GALGAME_PRESENTATION_ANALYZER_BASE_URL`, `GALGAME_PRESENTATION_ANALYZER_API_KEY`, and `GALGAME_PRESENTATION_ANALYZER_MODEL`) and pins provider `anthropic`, host `aiself.vip`, and model `claude-sonnet-4-6`. The service itself enforces that same provider, origin, and model, so inherited or manually supplied environment values cannot select another provider/model/host. The launcher starts Node with an explicit environment allowlist; unrelated API credentials from the invoking shell are not inherited. This key is independent of SillyTavern gameplay credentials and the visual-service credential. It is injected only into the server-side analyzer process; it is never printed, returned, or sent to the browser. Text annotation and scene-continuity requests send approved visible story text to that Claude endpoint; they do not generate story content or write to SillyTavern chats. The reset supervisor uses this same fixed launcher if the service is offline or running without an analyzer. For a standalone run, `node external-modules/presentation-analysis-service/server.mjs` still binds only to `127.0.0.1:8801` and reports `analyzerConfigured: false` unless all dedicated variables are set to the pinned provider, host, and model. Port 8801 is server-internal; player requests use the versioned fixed proxy paths on port 8798.

Text analysis on 8801 uses its dedicated Claude credential and pinned model `claude-sonnet-4-6`. Image understanding on 8798 remains on the separate visual credential and uses the OpenAI-compatible chat endpoint with `doubao-seed-2.0-pro`. All three credentials remain separate, server-side, and absent from the player browser. Story generation itself remains on SillyTavern's original runtime and active gameplay provider.

The direct environment configuration is reserved for isolated tests and diagnosis. The production launcher reads the local dedicated file and sets these values in its allowlisted child process:

- `GALGAME_PRESENTATION_ANALYZER_PROVIDER=anthropic`
- `GALGAME_PRESENTATION_ANALYZER_BASE_URL=https://aiself.vip`
- `GALGAME_PRESENTATION_ANALYZER_API_KEY` (server process only; never printed)
- `GALGAME_PRESENTATION_ANALYZER_MODEL=claude-sonnet-4-6`

The pinned Anthropic adapter uses `/v1/messages` and sends production annotation and scene-continuity schemas in the documented `output_config.format = { type: "json_schema", schema }` shape. It removes schema constraints the Anthropic grammar does not support (such as `maxItems`, `minLength`, and `maxLength`) from the provider schema and keeps them as descriptive guidance; the original local materializer and validators still enforce the complete application constraints. If an annotation or scene-continuity response is empty, truncated, or malformed JSON, one bounded retry switches that request to prompt-constrained JSON with the same schema included in the system prompt when it is not already present; the parser, candidate materializer, and full Annotation v1 validator remain authoritative for annotations, and the scene validator remains authoritative for scene continuity. This fallback does not apply to semantically invalid but parseable output, and it never lowers evidence requirements. The response parser accepts either one complete JSON value or one unambiguous JSON object wrapped in Markdown/prose; wrapper text is discarded and duplicate keys are rejected. Malformed, ambiguous, partial, or schema-invalid output is rejected after the bounded attempts. JSON parse diagnostics may include a UTF-16 offset relative to the exact parser input (trimmed response, fenced JSON body, or extracted JSON object), an allowlisted token class (including `fullwidth-comma` and `unicode-punctuation`), and an allowlisted parser stage (`expected-colon`, `expected-comma`, `invalid-value`, etc.); unterminated containers point to end-of-input. The one bounded Anthropic prompt-only retry uses that parser stage to request ASCII JSON punctuation where needed, while local parsing and evidence validation remain mandatory. Diagnostics never include the character, property name, model output, prompt, or credentials. The OpenAI-compatible adapter code remains covered only by isolated transport tests; service configuration cannot route production requests to it. Annotation calls disable the provider's default reasoning mode where supported.

For the Anthropic provider payload only, source strings in `visibleText` and evidence-cell `text` replace Chinese typographic double quotes (`“` / `”`) with ASCII double quotes. A live, low-volume differential probe found malformed JSON from the pinned gateway on a Chinese sample with typographic double quotes, while the same provider schema and input shape returned valid JSON for ASCII quotes and for Chinese text without those quote glyphs. This normalization is applied to a provider-only copy; SillyTavern chat text, source hashes, server-side source maps, evidence-cell spans, and final Annotation v1 validation continue to use the original characters. No other quote marks or punctuation are normalized.

Anthropic may echo those normalized ASCII quotes in optional entity/evidence strings. Before local materialization, the adapter restores a candidate string only when it is a whitelisted source-derived field and its normalized form has exactly one match in the original target message. An ambiguous quote-bearing optional claim is made invalid so the existing bounded recovery drops it; it cannot bind to a different original occurrence. This keeps evidence spans and hashes bound to the original chat text without fuzzy matching or relaxing acceptance rules.

The active `presentation-annotator.v26` route uses the same server-mapped source-unit/evidence-cell locator for ordinary and dense tiled requests. A request has one target message and returns exactly one result item containing one ordered classification for every owned source unit. Mixed units receive at most six grapheme-safe refinement levels under the existing request deadline and provider-call ceiling; unresolved units reject the annotation instead of being forced into a public label. `mixed` is a refinement-only control value, so provisional classification/speaker evidence attached to it is discarded before refinement; every final child still needs its own evidence. Historical v6 per-code-point markers and v18 quote/anchor boundary candidates are retired implementation paths; neither is used by production annotation requests.

Long, high quote/line-delimiter-density annotation messages use unit-aligned bounded tiles: non-overlapping source-unit cores of at most 600 Unicode code points with up to 48 code points of lookaround on each side and at most 60 quote/line delimiters per view. Ordinary annotation requests use the same source-unit protocol without tiling. The service builds exact source-unit spans (target 120–160 code points for longer text; short text preserves existing sentence/line boundaries) and smaller evidence cells (at most about 24 code points), assigning opaque request-local IDs. The provider sees text grouped by IDs and returns only unit classifications/speaker references plus evidence-cell IDs; it emits no numeric offsets, boundary quotes, or per-code-point markers. The service maps IDs to original spans, verifies one-to-one complete ownership, rebuilds segment hashes, and runs the full Annotation v1 validator. If provider rows are reordered or a non-mixed row has an unknown unit ID, the service may normalize it only when its current-request classification evidence cells all resolve to exactly one source unit, known IDs do not contradict that owner, and every source unit remains covered exactly once. Mixed rows have no classification evidence cells and therefore require a valid request-local unit ID. Mixed units are refined by grapheme-safe bisection for at most six levels; unresolved mixed content rejects the full request and remains unknown-safe. Every final segment must retain a segment-local `classification` evidence span before/after tile merge and at the final response boundary; lookaround-only evidence cannot authorize a core-owned display label. Entity, identity, and state claims continue through the existing exact-quote materialization and bounded optional-claim recovery. The complete merged result is validated against the existing Annotation v1 contract. Tiled requests start with a 4096-token output budget; if the provider explicitly reports JSON truncation, a retry may raise the cap to 8192. Their shared annotation deadline is 120 seconds, and tile provider attempts use that same shared budget; ordinary requests use the same route deadline. The player adapter and 8798 proxy allow 125 and 130 seconds respectively. Scene-continuity keeps its existing timeout budgets. Any unreconcilable ID/evidence mismatch, mixed-refinement limit, core/coverage/span/hash error, hard-limit breach, or final validation failure rejects the complete request; partial annotations are never returned.

Tiled annotation has a shared 120-second absolute deadline that includes provider-semaphore queue time, plus at most 24 actual provider calls per HTTP request including retries. All tile calls share one FIFO, process-wide semaphore with at most three actual model calls in flight. Real-provider comparison found that six concurrent calls intermittently received HTTP 400 while six calls at concurrency three all returned HTTP 200; three is the current measured safe cap. The service reserves every tile's base call before allowing retries, so base calls plus retries can never exceed 24. `MAX_INFLIGHT=2` limits concurrent HTTP requests but is not the provider concurrency limit. A provider HTTP 400 with structured `type=server_error` is classified as an upstream failure and receives at most one bounded retry under the same deadline, semaphore, and per-request provider-call ceiling. A failed tile aborts its queued and in-flight siblings and the request waits for them to settle before returning. Rejection logs include only fixed failure categories, allowlisted provider metadata, and bounded output-size diagnostics; HTTP provider failures may include a fixed-envelope class and allowlisted `type`, `code`, and request `param` values so opaque 4xx failures can be diagnosed without retaining free-form response text. Logs never include model text, prompts, or credentials. The public Annotation v1 DTO/schema and scene-continuity analysis contract remain unchanged; scene requests use the separate scene-continuity contract, though all provider calls share the process semaphore.

If a structurally sound result fails Annotation v1 only on a fixed allowlist of optional semantic fields, the service may recover locally: drop invalid attributes/entities/identity links/state claims; for speaker-attribution failures, remove only the invalid `speaker` evidence and downgrade the segment to `unattributed-dialogue`. The internal candidate case `kind=dialogue` with no speaker reference and no speaker evidence is also canonicalized to `unattributed-dialogue`, preserving its validated classification evidence. A missing speaker reference paired with speaker evidence is contradictory and remains rejected. After tile merge, this same fixed-allowlist recovery runs again because lookaround evidence may cross final segment boundaries; the recovered result is returned only after the complete Annotation v1 validator passes. Invalid classification or other non-speaker segment evidence is not recoverable. It must not infer a replacement value or convert unattributed dialogue to narration. Recovery reruns the complete Annotation v1 validator and is accepted only if it passes; unknown validator paths, malformed provider output, unreconciled unit IDs, span/hash/coverage errors, or a still-invalid recovered response continue to reject the complete request. Recovery diagnostics contain only bounded issue categories and item counts. Merged-output rejection diagnostics additionally record the fixed recovery outcome (`recovery-not-applicable` or `recovery-revalidation-failed`) and allowlisted initial/final validation categories as a separate field; they do not weaken acceptance or expose raw validator paths. The analyzer also enforces segment-local classification evidence after tile-core clipping and again at the final response boundary, so evidence that existed only in lookaround cannot authorize a public segment. This changes neither the public Annotation v1 schema nor SillyTavern chat data. The current presentation scope is `presentation-annotator.v26`.

Scene-continuity prompt v6 uses exact evidence quotes rather than numeric offsets; the service resolves each unique quote against the exact visible page and computes code point spans itself. Missing or ambiguous quotes receive bounded regeneration and fail closed if still invalid. Ordinary non-tiled calls retain their established bounded regeneration policy. Rejected results are logged only with a request ID, route, safe failure category, and bounded validation paths; prompt text, model output, and credentials are never logged. Redirects, non-HTTPS endpoints, URL credentials, query parameters, and hosts outside the explicit allowlist are rejected. The player sends no provider credential. Only the two configured loopback player origins are allowed by default; use `GALGAME_PRESENTATION_PLAYER_ORIGINS` to enumerate additional exact origins. The read-only `/v1/health` endpoint answers browser preflight only for an allowlisted origin requesting `GET`, including Private Network Access preflight when requested.

Annotation provider-failure logs also include bounded analysisProgress: planned/completed tile counts, actual provider attempts, maximum mixed-refinement depth, the last provider stage, last tile/attempt indexes, and time in that stage. The top-level providerAttempts field preserves the last three allowlisted attempt outcomes, including a bounded 120-second timeout duration. These fields distinguish semaphore wait, active provider call, and post-response validation without recording source text, prompt content, model output, entity names, request payloads, or credentials. This is diagnostic-only: the 120-second deadline, 24-call ceiling, retry policy, and validation requirements are unchanged.

## Stop / disable

Stop the Node process to disable the optional analyzer. The player should continue displaying original SillyTavern content in neutral/unknown presentation when this service is absent. Do not terminate the core SillyTavern or generation bridge to disable annotation.

## Verification

`node external-modules/presentation-analysis-service/test.mjs` exercises endpoint allowlisting, Anthropic `/v1/messages` structured-schema requests and fail-closed output parsing, health and Origin refusal without contacting an upstream provider. Live synthetic requests after restarting the service are required to verify the configured credential and upstream.
