# V86 复合职务称谓与直接引语归属 TaskSpec

## 目标

继续减少结构标题的旁白兜底，只新增一条跨剧本、低延迟的句法规则：当引语前出现唯一的复合职务称谓，并且该主体紧邻明确的动作/发言线索引出闭合直接引语时，将标题归给该称谓。不得按剧本名称、角色名单或当前剧情启停规则。

## 审计证据

V85 全量只读回放发现 1,201 个对话候选页仍为旁白兜底。抽样中至少有下列高证据格式未命中：

- `门卫头目收手，朝仓内挥了挥：“进。卸到内场三号秤……”`
- `一个收账鸦队长走来，声音闷在鸟嘴面具里：“新到押运队，三号秤验货。”`

两例共同点是角色头衔是由组织/地点描述词与职位词组成，句子主体位置清晰，并以动作或发言行为紧邻冒号引出完整引语。当前 bounded actor 表覆盖常见单一职业名和描述词，但不能解析这些复合头衔。不得把该观察扩成任意“名词+引号”规则。

`收账鸦队长` 的历史证据不是单句独立命中：同一条 assistant 原文在此前先出现“两名收账鸦”，随后出现“收账鸦盯了一眼”，再出现“一个收账鸦队长走来”。“收账鸦”不是当前 chat resource candidate；规则只有读取这段原文上下文并验证重复主体后才能接受它。测试夹具必须保留这个前文上下文。

V85 的只读回放有两个相关基线：不带逐聊天角色候选时 6,201 个对话候选页中 4,629 页有归属、1,322 页旁白兜底；加入聊天绑定资源候选后 6,277 个对话候选页中 4,853 页有归属、1,201 页旁白兜底。以上是覆盖统计，不是准确率。V86 的主要回测必须固定当前资源候选侧栏，并保留相同 source digest；不得把两种 roster 条件混成一个前后比较。

## 规则契约

1. 只处理闭合引语且引语紧接冒号/中文冒号的情况。
2. 主体必须是紧邻引语的局部主语。允许“一个/一名/一位”等单数引导词，后接复合称谓。复合称谓由 1–6 个汉字的前缀与职位头词构成，前缀必须满足至少一项：
   - 精确匹配本聊天的角色/资源候选名；
   - 精确匹配 V85 通用人类角色头词（允许加本地角色描述），本版增加常见 `门卫` 作为“门卫头目”的角色前缀；
   - 该前缀在当前 assistant 原文中、主体短语开始前至少两次作为独立名词短语出现，且至少一次处于动作主语位置并紧接已有动作 cue 或本版补充的 `盯了一眼`（测试例使用“收账鸦盯了一眼”）。提取和计数只扫描当前消息的不带引语部分；不把出现一次的任意名词拼接到职位词上。
   职位头词限于 `头目、队长、首领、领队、统领`。其余前缀如果不能由上述证据验证则 abstain。speaker span 只覆盖复合称谓自身，不包括单数引导词、助词或动作。
   前缀证据不足时，新规则必须 abstain，且不得清除或改写 V85 已能给出的结果；V86 只可增加有证据的命中，不可让旧版已有结果降级。
3. 主体后必须在同一主语动作链中出现现有结构化动作/发言 cue；仅本规则补充动作 cue `收手、挥了挥`。只出现“说、问、答、喊”等单字 cue 时，后接汉字必须满足词边界，禁止把“说明”识别为“说”。
4. 可跨逗号承接同一主体的无主语动作。若后续子句出现另一位角色/代词/群体作明确动作主语，拒绝归属；角色只作宾语不算换主语。
5. 引语若来自信件、告示、记录、物品、转述/朗读、心理活动或叙述者引用框架，继续沿用现有过滤器并拒绝归属。多主体、无动作 cue、非闭合引语、过长或无法精确切分的主体都 abstain。
6. 不把复合称谓自动登记为人物身份、别名、队伍成员或资源实体；它仅作为当前页面 display-title evidence。未知首次人物继续服从既有 `???` 规则。
7. 不改正文、原生 formatter/segmenter、分页、页序、sourceSpan、聊天、身份投影、头像绑定或 SillyTavern 原版。

## 验收

- 正例使用“门卫头目”历史结构、包含“收账鸦”两个前文实体提及的完整历史上下文、以及新造且前缀由 chat candidate/通用角色头词支持的组合职务名称；标题 span 精确等于复合称谓。
- 负例覆盖复合职务作为宾语、并列职务主体、后续动作换主语（包括第二复合职务主体）、未被聊天候选或前文重复确立的任意名词前缀（V86 不得新增归属，也不得退化 V85 已有结果）、信件/记录引文、心理活动、开引号未闭合、单字 cue 长词前缀。
- 运行 adapter、runtime regressions、candidate scopes、historical replay 测试；生成 player/admin 构建产物。
- 在同一历史 source digest、同一聊天资源候选侧栏下回测 V85/V86；固定全部原始页 cohort 并报告候选侧栏 digest、cohort digest、新增角色/群体归属、降级/改名、剩余旁白兜底。需满足同源同 cohort 且零旧结果退化；没有新增逐页 gold 时仍报告 `speakerAccuracy=INSUFFICIENT_EVIDENCE`。
- 独立只读代码审计 PASS；静态架构审计、原版冻结路径检查、`git diff --check` 通过；分页 formatter/segmenter 与上一版本逐字一致。

## 不做事项

- 不增加场景专名表，不扩展成泛化名词抽取，不因为标题里“有人名”就断定其说话。
- 不把全量旁白兜底清零作为目标；缺少唯一主体证据时继续保留旁白/匿名标题。
- 不以回放覆盖率作为准确率。

## 实施结果

实现 parser/cache 版本为 `full-message-speaker-index.v86`。结构规则始终使用同一个 shared parser，未新增剧本专属名称表或启停条件。新增测试覆盖“门卫头目”“收账鸦队长”完整前文、“星港护卫队长”聊天候选，以及复合称谓宾语、动作主体冲突、第二复合职务主体冲突、书面载体和前缀无证据时不扩增旧版归属。独立审计发现后续逗号子句此前只检查旧版主体类型，漏掉证据充分的另一复合职务主体；修复后会在相同复合前缀上下文下验证该主体的动作 cue，并拒绝将引语归给前一个人。缓存版本随此行为修正升至 v86。

同历史源文件、同候选侧栏的 V85/V86 只读回放：158 个聊天文件、955 条 assistant 消息、18,696 个页面；固定页面 cohort digest 为 `sha256:87d1205133acbfdf6ed2e51708e467fd014507ad5d3f002671d1dd5e910c3c55`，候选侧栏 digest 为 `sha256:ff38e7f7e08616324d7b788bb26a9f4c90aff475275c630cac016aff50e0b95d`，两轮 source digest 均为 `sha256:3cd35138de9729080525259936cb95376ee662b59691f917d4903a7bd47bd6bd`。6,277 个对话候选页中，带角色归属页从 4,853 增至 4,855；旁白兜底从 1,201 降至 1,199。两页是同一段连续引语，归为“收账鸦队长”；没有旧版角色归属降级。聊天源未变更、无聊天写回、无外部 provider 调用。此数据仅表示覆盖变化；缺少新逐页 gold，`speakerAccuracy=INSUFFICIENT_EVIDENCE`。

独立代码审计发现一个边界：后续逗号子句若出现另一个经上下文证据支持的复合职务主体并执行动作，原始冲突检测会漏掉。修复后该额外冲突拒绝规则使用独立 v86 门槛；回归断言确保相同文本在 v85 保留旧归属、v86 改为 abstain。测试正文为“收账鸦队长走来，灰狼队长挥了挥”，且“灰狼守卫”在同条消息此前两次作为动作主体出现。

修复后重新执行同源、同侧栏 V85/V86 回放，比较结果仍是两页由旁白改归“收账鸦队长”，无历史归属回退；source digest、18,696 页 cohort 和候选侧栏 digest 与上方记录相同。回放不写聊天、不调用外部 provider；没有新增逐页 gold，因此仍为 `speakerAccuracy=INSUFFICIENT_EVIDENCE`。

adapter、runtime regressions、candidate scopes、speaker replay 测试合计 151 pass、2 skip、0 fail；两个 skip 是 Windows 主机无法创建文件符号链接。player/admin 公共构建已重建并与暂存构建逐文件一致（33/22 文件）。静态架构审计 `ok=true`、`prohibitedActiveCount=0`、`needsReviewCount=0`、`failedChecks=[]`。原版 SillyTavern 冻结路径无改动。分页函数 `formatVisualNovelDisplayText` 与 `createVisualNovelDisplaySegments` 和 V85 快照逐字一致，SHA-256 分别为 `d04bbcdf45d499e2fc79fab4bae940b1985840f7aa1c9081f6a7d25610eeb77d` 与 `40e2e454d76127b52fd335b0111ed58e3c5c1fdddf59c703e413174f1d426ea9`。独立只读审计 PASS：确认 v85/v86 门槛、指定错归属复现、player/admin 同步构建、分页函数逐字一致及 SillyTavern 冻结边界。
