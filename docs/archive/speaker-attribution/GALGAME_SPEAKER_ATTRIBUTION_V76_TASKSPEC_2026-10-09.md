# 说话人结构化归属 v76 开发说明

## 目标

从现有聊天里仍频繁落入旁白兜底的引语中，识别可复用的局部句法结构；在不猜测邻近人名、不改变正文分页的前提下，提升角色标题覆盖率。

## 范围与硬边界

- 代码范围限于 `frontend/shared/src/sillytavern-adapter.js`、播放器 parser/cache 版本、历史回放工具、对应测试及本开发文档。
- 不修改原版 SillyTavern、聊天内容、角色身份/名册、人物状态、头像绑定或剧情正文。
- SillyTavern 既有 segmenter、正文 formatter、页序、页数和 source spans 是输入真值；标题侧车不能写回这些数据。
- 只改变 display-title evidence。没有逐页 gold 时，准确率必须报 `INSUFFICIENT_EVIDENCE`。

## 发现的重复形态

既有规则已经覆盖了明确的行首署名、名册发声 cue、很多动作引语和代词回指。剩余内容中仍反复出现两类局部关系：

1. 人名位于引语引入子句句首，紧跟可观察动作，子句以冒号直接引出配对引语。动作可以是整理物件、吹口哨、翻白眼、弯腰拾物、从遮蔽物中探出等。旧规则有时会把后续动作/物件误当主体，或因名册缺失而不认句首的人名。
2. 一段引语已经由唯一角色明确署名；其后只有一条短的“他/她 + 动作/状态”叙述，接着出现新的未署名引语。这里的证据是“已归属引语 → 短代词动作桥 → 新引语”的顺序关系，而不是从代词本身猜身份。

相应的拒绝边界也很重要：“有人/某人”等不定指不是角色名；并列行动者不构成唯一归属；引用信件、系统信息、心声或新场景时不能继承前一角色。

## 已落地的 v76 规则

parser/cache namespace：`full-message-speaker-index.v76`。

### 规则 A：句首具名主体 + 动作 + 冒号引语

仅处理已闭合引语，且引语前的当前子句必须以 `:` 或 `：` 直接结束。先使用精确名册姓名；没有名册时，才从句首主体位置恢复符合姓名形态的拉丁名或短汉字名，并要求后面紧接可观察动作。

遇到句界、标题、引号/引用载体、心声、书面来源、并列主体、不定指人物，或后续子句出现竞争的人名/代词/泛称角色/另一个动作主体时放弃归属。该规则只产生展示用说话人证据，不创建持久角色身份。

### 规则 B：引语之间的短代词动作桥

当前闭合引语没有更强归属证据时，只检查同一原始消息中紧邻的上一段引语。上一段必须已经有唯一明确说话人；两段引语之间最多 112 个源字符，且原文含段落换行；桥接内容必须是一句简短的“他/她 + 可观察动作/状态”。发生场景切换、书面引用、心声/来源切换或说话人竞争时放弃继承。代词本身不能建立新身份。

比较使用完全相同的聊天集合和消息源摘要：`sha256:3cd35138de9729080525259936cb95376ee662b59691f917d4903a7bd47bd6bd`。

两条规则带来可测但有限的覆盖提升，没有解决大多数剩余兜底。剩余例子里仍有长篇混合对白、记录/状态内容、泛称人物、同页多说话人，或缺少唯一局部署名的引语。不能为了降低兜底数而改成“随便选最近姓名”；应继续按反复出现的结构簇推进，并给每条新规则同时增加负例。

其中“句首具名主体 + 动作 + 冒号引语”在历史回放投影 27 页；短代词动作桥未在这 158 个聊天里命中，现有证据来自正反合成用例，尚无历史覆盖收益。

这只是覆盖变化，不是准确率。全量聊天缺少匹配到每一页的人工 gold；158 个聊天也都没有可用的发布名册 scope，所以 speaker accuracy 仍为 `INSUFFICIENT_EVIDENCE`。统计显示源未改变、无聊天写回、无外部模型调用。
