# Galgame 说话人归属 v73 TaskSpec

## 目标与根因

处理闭合引语前出现“他/她/它 + 明确发声 cue”，但角色名位于同一消息更早的动作句/已署名对白处、因而旧规则不能稳定回指的少量结构。v72 的“邻句只要提到已知姓名就归属”命中历史 15 次，但抽查出现选项内容、被谈论角色、无关相邻对白等误归属；扩大裸姓名提及不能作为安全的覆盖率优化。

## v73 规则

- 所有已有显式署名、动作主体、引语配对、玩家/群体等规则先执行。
- 仅在闭合引语没有任何既有候选时运行低优先级回指。
- 回指框架必须是引语前的 `他/她/它 + 明确发声 cue`；检查最近两句/分句中的唯一动作主体，或最近、唯一且仍在当前消息内有效的显式说话人锚点。
- 人物候选必须唯一。局部区域内出现两个及以上已知角色名时放弃猜测；书面载体、思考/来源转述、并列主体、插入其他引语/场景边界时拒绝归属。
- 不创建角色身份，不修改 roster、头像绑定、原始消息正文、分页器、source spans、页序、生成请求或聊天数据。只产生源跨度绑定的 display-title evidence。
- 页面仍按原有分类路径处理；缺少唯一可靠证据时保留旁白兜底。

## v72 与 v73 的继承关系

v73 取代 v72 的 `nearby-known-name-mention-fallback`，保留此前已验证的强结构规则与 chat-local scope 保护。v72 的宽松姓名提及只用于历史对照，不能作为当前默认行为。v73 新规则不能扩展为“任意邻句人名”；若未来调整，必须同时回放误归属负例。

## 回归负例与验收

- `尼布看向Pippa。她低声说……`、`Pippa递给尼布一瓶药。他说……` 必须保持歧义，不按单个动作主体猜测。
- 动作主体唯一且代词发声的局部结构可归属；写信/报告/消息转述不能归属给消息来源。
- 选项、状态块、标题、被提及者、声音拟态不因邻句姓名变成角色说话。
- shared adapter、speaker replay、runtime regressions、语法检查和 `git diff --check` 必须通过；完整历史 replay 必须记录 digest、计数、无写回/无 provider 调用。
- player cache/parser namespace 与 shared parser 同步到 v73；静态 player/admin 构建输出按已审查的构建流程更新。
- 本轮不得修改 `createVisualNovelDisplaySegments` 的正文分页实现，也不得触及冻结的 SillyTavern 原版路径。
- 独立只读 A1 审计通过后方可报告完成。
