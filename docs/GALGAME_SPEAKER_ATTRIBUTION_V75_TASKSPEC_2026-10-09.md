# Galgame 说话人归属 v75 TaskSpec

## 目标

修复完整消息说话人索引中两类相互关联的问题：

1. 角色前的篇章连接词（例如“随后/接着/然后/这时/此时/突然”）会被汉字姓名提取吞入说话人标题，或阻断已知角色名与后续动作/发声 cue 的匹配。
2. cue 角色解析过度依赖通用中文前缀切分；在精确角色名之前出现篇章连接成分时，可能产生拼接后的伪角色名。

## 设计

- 仍以原始完整消息中的成对引语为识别单位，不把显示页当成句子或说话回合。
- v75 新增名册 cue 提取：在明确发声 cue 所在的局部子句中，先去除有限的句首篇章连接成分，再按完整名册名称和原始 span 识别角色；只有 cue 与角色处于同一可解析子句、且不存在通用群体主体时才归属。
- 页级独立切词若把连接词或声音修饰词并进姓名，仅当完整消息解析已给同一引语得到 rank-0 speaker，且页级名称以同一原文姓名开头、页级/完整消息 cue 都止于同一引语时，页级解析才采用完整消息的精确 speaker span。此兼容不会跨引语、不会补造身份，也不会依靠页文本邻接继承。
- 保留现有候选来源的优先级和保护性短路：上一轮回归发现无条件加入相邻引语 cue 会把原本正确的 Timmy 引语判成多说话人冲突，因此 v75 不放宽所有候选门槛，也不按单纯距离强行猜人。
- 普通附近人名、引号内提及、信息载体、并列主体仍不能作为说话人证据；不增加模型调用或角色持久身份。
- parser/cache/replay 版本升为 `full-message-speaker-index.v75`，v74 显式回放保留原行为。

## 严格边界

- 只改 `frontend/shared/src/sillytavern-adapter.js`、对应 shared/player 测试、玩家 parser cache/replay 版本和本文档/产品基线。
- 不改 SillyTavern 原版代码、聊天 JSONL、正文显示、分段器、分页、页面类型、source spans、语义标注、角色状态或图像匹配。
- 不进行聊天写回，不调用外部模型/API。

## 验收

- v75 将“随后尼布低声说：……”归为“尼布”，speaker span 精确覆盖原名；相同测试在 v74 保持旧结果。
- 连接词后是无名群体主体时不得错误继承前一角色；并列主体继续拒绝。
- 全量 adapter、player runtime regression、speaker replay tests 通过；历史回放只有在聊天文件存在时才报告。历史目录为空时明确记为未能回放，不能虚构覆盖率或准确率。
- 静态确认分页函数及 SillyTavern 冻结路径没有改动；`git diff --check` 通过。
